## Course outline

1. **Day 1** — where containers came from, image vs. container, container vs. virtual machine. First containers: `run`, `ls`, `stop`, `logs`, `attach`, `rm`, `--rm`, `-d`, `-it`. Configuration through environment variables and `.env` files, publishing ports, `inspect`, and container states.
2. **Day 2** — persistent data: anonymous and named volumes, bind mounts, the user inside a container. Connecting containers (MySQL + Adminer) and **Docker Compose** (WordPress).
3. **Day 3** — restart policies and building images: `Dockerfile`, layers and cache, pushing to a registry (`ttl.sh`). Packaging your own Python app following best practices: linter, the right base image, multi-stage builds, vulnerability scanning, a non-root user, healthchecks.
4. **Day 4** — aliases, Docker contexts, resource limits. Management tools (dry, Portainer), a private registry, Traefik, Watchtower.

:::tip[The long syntax]
> "As a teacher I will show you the explicit form. You, as people from practice, are free to make your lives harder with the short one."

The notes therefore always use `docker container run`, `docker container ls`, `docker image ls` instead of `docker run`, `docker ps`, `docker images`. Why is explained in [First containers](/devops-notes/en/docker/prve-kontajnery/).
:::
