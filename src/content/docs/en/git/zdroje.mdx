## Corrections to the lecture

Checked on Git 2.50.

- **Commit does not move files into staging.** `git add` puts them there, `git commit` saves them to the local repository, and only `git push` sends them to the server.
- **`git commit file` without `add`** (slide 24) works only for files Git already tracks. In the course it failed because the file was new: *pathspec 'F3' did not match any file(s) known to git*.
- **`git show` with two hash characters** did not work and the claim was that you need the full ID. A unique prefix of at least 4 characters is enough.
- **`.gitignore` does not use regular expressions** but glob patterns. And a pattern without a slash (`program`) applies in every folder, so after moving into `code/` the files stay ignored; root only is `/program`.
- **`git rebase main` does not combine commits into one.** It moves them onto a new base as new commits (two remained in the demo). Combining is done by `git rebase -i` (squash/fixup) — slide 78.
- **HTTPS and the account password:** GitHub does not accept the account password for Git; HTTPS uses a personal access token or a credential manager.
- **`git stash push`** sends nothing to the server — "push" only means putting it on the stack.
- **`git pull` with diverged branches** in newer Git ends with *Need to specify how to reconcile divergent branches* unless `pull.rebase` is set. The notes use `git pull --no-rebase` (as in the instructor's cheat sheet).
- In `git show`, an annotated tag differs from a lightweight one by the `tag …`, `Tagger:`, `Date:` header and a message before the commit.
- Slide 15: `sudo apt-get update && apt-get install git` — the second command needs `sudo` too.
