The **Kubernetes 101** course (four days) is taught by Mirek. The notes are based on transcripts of all four days, the slides of the first three days, and the lab material with solutions. They are organised by topic, corrected, and extended with questions and exercises. Topics from the slides that weren't covered in class (e.g. creating a cluster with K3d, the MinIO lab, the DaemonSet demo with Telegraf) are left out or only mentioned.

:::note[What is deliberately left out]
The OpenWeatherMap API key from the slides and materials is replaced with the placeholder `<API_KEY>`, the lab machines' IP addresses with `<IP>`. The lab machines' password and participants' names are omitted. Credentials in the labs (`secret`, `top.secret`, `wpuser`/`end321`, `janosik`/`valaska123`) are practice values.
:::

:::caution[The commands were not run]
No Kubernetes cluster (nor Docker) was available while these notes were written, so the commands were not run as they were for the Git course. Behaviour was checked against the Kubernetes documentation, the slides, and the course recording.
:::

## Corrections

- **Instructor (day 1):** "Docker came out as version 1 in 2013" — Docker appeared in 2013, version 1.0 came out in 2014. Kubernetes 1.0 and Docker Swarm 1.0 came out in 2015.
- **Instructor (day 1):** the name Kubernetes — the Greek *kybernétés* is a helmsman.
- **Instructor (day 1):** an odd number of masters is because of the etcd quorum (a majority), not an "uneven vote" after a failure.
- **Instructor (day 1):** LoadBalancer services in K3s aren't handled by Traefik but by the built-in **ServiceLB** (Klipper). Traefik is the Ingress Controller on ports 80/443.
- **Slides (day 1):** "Ingress is a special case of a LoadBalancer service" — Ingress is a separate object with rules; the controller is usually exposed through a LoadBalancer.
- **Slides (day 2):** "request ≤ value < limit" — actual usage can also be below the request (the instructor said so himself in class).
- **Slides (day 2, image):** the Redis example uses `apiVersion: extensions/v1beta1`; today it's `apps/v1`.
- **Instructor (day 3):** the HPA target `--cpu 50` is 50 % of the CPU **request**, not 50 % of a core.
- **Instructor (day 3):** `minReplicas` and `maxReplicas` aren't in the deployment but in the HorizontalPodAutoscaler object (the instructor checked this on day 4).
- **Material (day 3):** in the Morning Exercise all four deployments have the same selector `app: rambo` — the selectors overlap. The notes add `city` to the selector. The containers in the solution are called `rambo-mu`, `rambo-ke`…, so `set image … rambo=…` wouldn't match them.
- **Slides (day 3, cheat sheet):** `kubectl delete configmap credentials` for a Secret — correctly `kubectl delete secret credentials`.
- **Material (day 3):** the Traefik dashboard via port 9000 — in the new Traefik it's on 8080 (`deploy/traefik 8080:8080`, as on the slides).
- **Instructor (day 4):** `ReadWriteOnce` = mounted read-write from **one node**, not from one pod.
- **Instructor (day 4):** the PVC stayed `Pending` because without `storageClassName` it got the default class `local-path` (which also waits for a pod — `WaitForFirstConsumer`), while the manual PVs had no class. That's why the solution uses `storageClassName: ""`.
- **Instructor (day 4):** `kubectl delete pv` on a bound PV doesn't delete it immediately — it stays `Terminating` while the PVC exists.
