## Course project

Throughout the course we build one workflow:

<Pipeline steps={[{ group: 'Healthcheck', steps: ['OpenWeatherMap', 'RustFS'] }, 'Scrape Data', 'Validate Data', 'Process Data', 'Publish Data → S3']} caption="Scrape sends JSON, Process returns a CSV line. From day 4, publishing is followed by the report_builder DAG (triggered by an asset)." />

1. **Day 1** — the workflow as a Python script split into three functions: functions, HTTP, JSON, CSV, and exceptions.
2. **Day 2** — the script becomes a command-line tool (click); then Apache Airflow: installation, the first DAG, tasks and XCom, Connections and Variables.
3. **Day 3** — Airflow as a systemd service; validating data with JSON Schema, project structure (pathlib, `constants.py`), logging and errors, healthchecks (ping, sh, HTTP) running in parallel with retries. From the slides: RustFS/S3 and boto3, task groups, and dynamic mapping for several places.
4. **Day 4** — task groups, connection names as constants, and `helpers.py`; the dataset is stored in S3 (RustFS, boto3, temporary files), and its update triggers a second DAG, `report_builder`, through **assets**.
5. **Next** — the report, notifications to your phone (Pushbullet — install the app beforehand), and dynamic task mapping for several places.
