## Corrections to the slides

- OpenWeatherMap response keys: `main.temp` (not `main.temperature`), `sys.sunrise`, `sys.sunset`, `sys.country`, and the city in `name`.
- The slides' cheat sheet has `add(10 + 20)` — it should be `add(10, 20)`.
- The click example calls a `validate_schema()` function that the slides never define; the notes contain a complete, tested `workflow.py`.

### Day 2 (verified on Airflow 3.3.2)

- `catchup` defaults to `False` in **Airflow 3** (the slides say `True`, which held in Airflow 2).
- The `.test()` parameter is `logical_date`, not `execution_date`; `airflow dags trigger` takes `-l/--logical-date`, not `-e`.
- The healthcheck with `retries=3` raises `AirflowFailException` — which **skips** retrying. Retries need a normal exception.
- The final DAG in the slides: `process_data(measurement)` uses a variable that does not exist (should be `data`), `upload_data` should be `publish_data`, `units` is `'metrics'` (should be `metric`), and the arguments of `scrape_data(query, appid, units)` are in a different order than its parameters.
- The PostgreSQL Docker compose mixes the Bitnami image's variables (`POSTGRESQL_…`) with the official `postgres` image; the connection string has a typo, `airflowow`.
- In the cheat sheet: `logging.getLogger(__file__)` → usually `__name__`; the “error-level message” example uses `logger.warning`.
- For the VS Code server cleanup script: the comment says “every two hours”, the crontab entry is `@midnight`, and the file names differ (`vscode-cleanup.bash` vs `vscode-server-cleanup.sh`).
- The short day 2 `airflow.cfg` made tasks fail (no `jwt_secret`) — the notes describe the generated-config approach.

### Day 3 (verified on Airflow 3.3.2)

- RustFS healthcheck: `raise AirflowFailException(RustFS service is unhealthy.')` is missing its opening quote.
- The boto3 and `publish_data` examples call `minio.Bucket(...)`, but the variable is named `storage`. The first `publish_data` version has a `line` parameter while the DAG calls `publish_data.expand(entry=...)` — the argument name in `.expand()` must match the parameter.
- `Path(mkstemp(...)[1])` leaves the file descriptor open; the notes close it with `os.close(fd)` and delete the temporary file in `finally`.
- A slide claims a `Param` in the DAG function's signature does not get registered. On Airflow 3.3.2 it does (with its type and title); the value is still available only inside a task through the context, so the `params=` + `get_current_context()` approach stands.
- The lab text speaks of “the MinIO service”, but the compose file runs RustFS. The cheat sheet's credentials are replaced with placeholders.
- Lecture: with the sh module, `ping(host, timeout=2)` does **not** replace `-w 2` — sh turns it into the option `--timeout=2`. Use `ping("-w", 2, host)` or `_timeout=2`.
- Lecture: a task with `retries=3` ran 4 times — that is correct (the first run + 3 retries).
- Lecture: `from airflow.exceptions import AirflowFailException` reports *deprecated* in Airflow 3; use `from airflow.sdk.exceptions import …`.
- Lecture: the relative import `from .constants import …` in a DAG file does not work even with `dags/__init__.py` (*attempted relative import with no known parent package*); `from constants import …` works.
