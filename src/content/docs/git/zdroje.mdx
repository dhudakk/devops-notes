## Opravy oproti prednáške

Overené na Git 2.50.

- **Commit nepresúva súbory do stagingu.** Do stagingu ich dáva `git add`, `git commit` ich uloží do lokálneho repozitára a na server ich pošle až `git push`.
- **`git commit subor` bez `add`** (slajd 24) funguje iba pre súbory, ktoré Git už sleduje. Na kurze zlyhal, lebo súbor bol nový: *pathspec 'F3' did not match any file(s) known to git*.
- **`git show` s dvoma znakmi hashu** nefungoval a zaznelo, že treba celé ID. Stačí jednoznačný začiatok s aspoň 4 znakmi.
- **`.gitignore` nepoužíva regulárne výrazy**, ale glob vzory. A vzor bez lomítka (`program`) platí v každom priečinku, takže po presune do `code/` súbory ostanú ignorované; iba v koreni je `/program`.
- **`git rebase main` nespája commity do jedného.** Prenesie ich na nový základ ako nové commity (v deme ostali dva). Spájanie robí `git rebase -i` (squash/fixup) — slajd 78.
- **HTTPS a heslo účtu:** GitHub heslo účtu pre Git neprijíma; pri HTTPS sa používa personal access token alebo správca prihlasovacích údajov.
- **`git stash push`** neposiela nič na server — „push“ znamená iba odloženie na zásobník.
- **`git pull` pri rozídených vetvách** v novšom Gite skončí *Need to specify how to reconcile divergent branches*, ak nie je nastavené `pull.rebase`. V poznámkach `git pull --no-rebase` (ako v lektorovom ťaháku).
- Anotovaný tag sa od jednoduchého v `git show` líši hlavičkou `tag …`, `Tagger:`, `Date:` a správou pred commitom.
- Slajd 15: `sudo apt-get update && apt-get install git` — druhý príkaz potrebuje tiež `sudo`.
